# Rules and checks

Every rule below points to a Human Interface Guidelines page and was confirmed on the live page when it was added. At runtime, `hig_checklist`, `review_swiftui` and `check_contrast` fetch that page again and quote the sentence (or table row) the rule is based on. If Apple has reworded it, the citation comes back as `verified: false`, with no quote. `npm run smoke` re-checks every rule against the live site.

The "What to look for" text is our own paraphrase. Apple's wording appears only in the live quotes. The registry is in [`src/rules/registry.ts`](../src/rules/registry.ts).

## SwiftUI heuristics (`review_swiftui`)

`<platform>` means the per-platform rule variant, for example `controls.size.macos`. iPadOS uses the iOS rules.

| Check | Rule | What it flags | Known false positives |
| --- | --- | --- | --- |
| `hit-target-size` | `controls.size.<platform>` | Button, Link, Toggle, Menu or onTapGesture view with a literal .frame smaller than the platform's default (medium) or minimum (high) control size. | Hit area enlarged elsewhere (contentShape on a padded parent, a custom ButtonStyle); frames on decorative images are ignored. |
| `fixed-font-size` | `type.dynamic-type` | .system(size:), .custom(_, fixedSize:) or UIFont.systemFont(ofSize:) — sizes that do not follow Dynamic Type. .custom(_, size:) scales with body and is not flagged; @ScaledMetric sizes are skipped. | Deliberately fixed text (e.g. a large clock face) or sizes scaled manually elsewhere. |
| `font-below-minimum` | `type.size.<platform>` | Literal font size below the platform minimum text size. | Tiny decorative glyphs that are not text. |
| `hard-coded-color` | `dark.adaptive-colors` | Color(red:green:blue:), Color(hex:), Color(.sRGB, …), Color(white:), UIColor(red:…), #colorLiteral, and fixed .black/.white foregrounds/backgrounds. | Brand colors intentionally fixed and checked in both appearances; colors only used in previews. |
| `icon-only-button-label` | `a11y.labels` | Button whose label is only an Image, with no Text/Label and no .accessibilityLabel. | Some SF Symbols provide a default VoiceOver description; labels set by a custom ButtonStyle or a wrapper view. |
| `tap-gesture-as-button` | `buttons.press-state` | onTapGesture on a non-shape view without .accessibilityAddTraits(.isButton): acts as a button with no press state and no button trait. | Supplementary taps that duplicate a real control; views that implement their own pressed appearance. |
| `ignores-safe-area-content` | `layout.safe-area` | .ignoresSafeArea()/.edgesIgnoringSafeArea on a container or custom view rather than on a background (Color, gradient, Image, shape, Map, or inside .background). | Custom views that are themselves backgrounds; containers whose content handles insets itself. |
| `screen-bounds-layout` | `layout.size-classes` | UIScreen.main.bounds, UIDevice.current.orientation or userInterfaceIdiom used in view code. | Non-layout uses (analytics, one-off sizing of offscreen rendering); idiom checks for behavior rather than layout. |
| `alert-button-count` | `alert.max-buttons`, `actionsheet.max-buttons.watchos` | .alert actions with more than three Buttons; on watchOS, .confirmationDialog with more than four including Cancel. | Buttons inside conditionals that never all show at once. |
| `segmented-count` | `segmented.count` | Picker with .segmented style and more literal .tag() options than the HIG suggests (5 on iPhone, 7 in wide layouts). | iPad-only or Mac layouts reviewed with platform "ios"; pass the right platform. |
| `light-font-weight` | `type.light-weights` | .ultraLight, .thin or .light font weights. | Large display text where light weights stay legible. |
